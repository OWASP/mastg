## Identifying Sensitive Data

In order to protect sensitive data pragmatically in mobile applications, an organization needs to answer 3 points:
- The data classification policy (what's the value of sensitive data?)
- The data threat model (which type of sensitive data is at risk?)
- The data state model (in which state sensitive data is accessible?)

### Data classification policy

OWASP MAS does not answer the value data have for an organization. Not all information requires the same level of protection, however it's the organization's responsibility to decide what data is considered sensitive. A proper classification policy may identify the value of sensitive data based on their type (next section).

Additionally, classifications of sensitive information differ by industry, sector, and country. For example two commonly used data classification policies are:
- In the business sector, labels such as Public, Sensitive, Private, Confidential.
- In the government sector, labels such as Unclassified, Unofficial, Protected, Confidential, Secret, and Top Secret.

A definition of "sensitive data" must be decided before testing begins because detecting sensitive data leakage without a definition may be impossible.

### Data threat model

The data threat model identifies the type of data that's at risk. In the area of mobile apps there are two types:

- Attacks against Intellectual Property
- Attacks against User data

#### Intellectual Property data

This includes data used by the applications to function securely such as API keys, secrets, and certificates.

An adversary with such data in their possession may not directly exploit other users. However they may allow them to perform actions with their own accounts such as privilege escalation and bypassing access controls, bypassing payments, or perform actions against the company's infrastructure.

The list of intellectual property data includes:
- API keys, secrets or certificates that an application used to authenticate itself to its own backends
- API keys, secrets or certificates that an application used to authenticate itself to another 3rd party service (such as Crashlytics, Google Maps)
- Any technical data generated by the app (or its related systems) and used to protect other data or the system itself (e.g., encryption keys)

#### User data

This includes data related to a particular user of an application such as personal information, financial information, and health information. Secrets, key material, or certificates used to authenticate a particular user with a backend service also fall into this category.

The list of user data includes:
- Personally Identifiable Information (PII) that can be abused for identity theft: social security numbers, credit card numbers, bank account numbers, health information
- User authentication information (credentials, PINs, etc.)
- Financial information
- Health information
- Device identifiers that may identify a person
- Key material used to encrypt user data
- API keys, secrets or certificates that a user needs to access their account (e.g., JWTs, OAuth tokens, session cookies)

### Data States

There are three general states from which data may be accessible:

- **At rest** - the data is sitting in a file or data store
- **In use** - an app has loaded the data into its address space
- **In transit** - data has been exchanged between mobile app and endpoint or consuming processes on the device, e.g., during IPC (Inter-Process Communication)

The degree of scrutiny that's appropriate for each state may depend on the data's importance and likelihood of being accessed. For example, data held in app memory may be more vulnerable than data on web servers to access via core dumps because attackers are more likely to gain physical access to mobile devices than to web servers.

### MAS-ASSET Matrix

In close relationship with data classification come MAS Testing Profiles(link) and subsequently their outlined MAS Tests which aim to evaluate applications. MAS Testing Profiles are designed to identify the series of tests that should be performed to assess the security of an application. MAS Asset classification is used to identify which data a test is assessing.
